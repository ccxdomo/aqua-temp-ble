## Decisions
- Dependency-ordered implementation: registers constants landed BEFORE the flow stage
  (FR-3 consumes PUSH_TEMP_BLOCK_START) — deviation from tasks.md block order, documented.
- New step_id `confirm_push` instead of mutating the classic confirm description
  (additive translation, existing keys untouched).
- confirmed = registers.PUSH_TEMP_CONFIRMED OR entry option (global one-line calibration
  fix + per-entry gate, WRITE_ECHO_EXPECTED precedent).
- Options-flow push_temp_confirmed toggle added (judgment call: calibration can happen
  post-setup; the confirm checkbox alone would force re-adding the entry).
- Coordinator reads the T-block capture's last_seen for freshness; from_pushes withholds
  raws from the entity plane when unconfirmed (one mechanism enforces the honesty gate).

## Lessons learned
- HA's AddEntitiesCallback is called SYNCHRONOUSLY by platforms — a test fake must be a
  plain function, an async one silently never runs (RuntimeWarning, empty entity list).
- The config-flow fakes must raise instances of the REAL AquaTempTimeoutError class from
  the synthetic package, or the flow's except clause never fires.
- A test stub SimpleNamespace lacking `.data` breaks new code reading config_entry.data —
  stubs should mirror the real object's full shape.
