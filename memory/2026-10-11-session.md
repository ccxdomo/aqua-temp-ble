  (the data-model §6 T-window mapping), PUSHED_MIRRORS, PUSHED_SENSORS, PUSH_PLANE_FIRST/LAST;
  check_registry_integrity gained the pushed plane (window 2001-2090, duplicates,
  temperature-key-only rule).
- config_flow.py: the push-harvest stage (after probe-None, before the re-raise): 30 s
  zero-TX listen; a 2046 push => test SUCCEEDS with mode "push"; new confirm_push step
  (calibration checkbox push_temp_confirmed); options-flow toggle for push entries;

- coordinator.py: mode branch in _async_update_data; _async_update_push (zero requests,

- 5 new test files (35 tests), red-first each; census 009 idle-summary level re-pinned to
  WARNING; 011 suite fakes gained harvest_pushes{} and data={} stubs (assertions untouched).

## Decisions
- Dependency-ordered implementation: registers constants landed BEFORE the flow stage
  (FR-3 consumes PUSH_TEMP_BLOCK_START) — deviation from tasks.md block order, documented.
- New step_id `confirm_push` instead of mutating the classic confirm description
  (additive translation, existing keys untouched).
- confirmed = registers.PUSH_TEMP_CONFIRMED OR entry option (global one-line calibration
  fix + per-entry gate, WRITE_ECHO_EXPECTED precedent).
- Options-flow push_temp_confirmed toggle added (judgment call: calibration can happen
  post-setup; the confirm checkbox alone would force re-adding the entry).
- Coordinator reads the T-block capture's last_seen for freshness; from_pushes withholds
  raws from the entity plane when unconfirmed (one mechanism enforces the honesty gate).

## Lessons learned
- HA's AddEntitiesCallback is called SYNCHRONOUSLY by platforms — a test fake must be a
  plain function, an async one silently never runs (RuntimeWarning, empty entity list).
- The config-flow fakes must raise instances of the REAL AquaTempTimeoutError class from
  the synthetic package, or the flow's except clause never fires.
- A test stub SimpleNamespace lacking `.data` breaks new code reading config_entry.data —
  stubs should mirror the real object's full shape.

## Lessons learned
- Red-first staging works across task blocks: the revival branch
  referenced the not-yet-implemented from_merged/
  _log_trigger_answered_once (attribute resolution at call time), so
  AC-1..3 went green after Block 2 while AC-4 stayed red for exactly the
  missing Block 3.2 methods (the AttributeError named them) — no
  scaffolding needed.
- A suite pin restated in N places needs N inversions — count the pin's
  instances BEFORE declaring "one assertion changed".
- A fake whose read_registers returns a dict by default silently flips
  every push-mode test into the revival world (from_merged paths break
  the from_pushes field assertions); script the EXPECTED world by default
  and opt into the speculative one explicitly.
